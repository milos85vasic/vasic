**شغّل خادم بريدك الإلكتروني كالمحترف — صِفه بلغة JSON وانشره في أي مكان.**

## ملخص

Mail Server Factory أداة جاهزة للإنتاج تُعنى بتوفير خوادم البريد الإلكتروني بشكل آلي. يكتب المستخدم إعدادات بسيطة بلغة JSON، ثم يقوم المصنع بتفسيرها وتنفيذ جميع عمليات التثبيت والإعداد على نظام التشغيل المستهدف، لنشر مجموعة بريدية قائمة على Docker ومفككة الارتباط عبر ١٢ نوعًا من الاتصالات.

## وصف مختصر

أداة Kotlin/Shell تحول وصفًا بلغة JSON إلى خادم بريد إلكتروني مثبت بالكامل ومُحَوَّسَن باستخدام Docker. تدعم ١٢ نوعًا من الاتصالات (SSH، Docker، Kubernetes، AWS SSM، Azure، GCP، Libvirt، وغيرها)، إطار أمان كامل، ٢٥ توزيعة Linux، وتأتي مع ٤٣٩ اختبارًا ناجحًا.

## وصف مفصل

إن إعداد خادم بريد إلكتروني حقيقي وآمن يعد من الطقوس الكلاسيكية في إدارة الأنظمة — ومن أكثرها إيلامًا على نحو موثوق. يجب أن تتوافق جميع المكونات مثل Postfix وDovecot وشهادات TLS وسجلات DNS وقواعد جدار الحماية وخواص كل توزيعة بشكل مثالي، حيث أن خطأً واحدًا في التوجيه قد يؤدي إلى رفض الرسائل بصمت أو تحويل الخادم إلى مرسل مفتوح. تلتقط أداة Mail Server Factory كل تلك الخبرة المكتسبة بشق الأنفس والمعرضة للأخطاء وتحوّلها إلى برنامج. فبدلًا من تهيئة كل جزء يدويًا على نظام تشغيل غير مألوف، يكتب المستخدم النتيجة المرجوة بوصف بسيط بلغة JSON؛ ثم يقرأ المصنع هذا الوصف وينفذ خطوات التثبيت والإعداد الدقيقة المطلوبة على نظام التشغيل المستهدف، ليُنشئ مجموعة بريدية تعمل على Docker حيث تكون جميع المكونات مفككة الارتباط — وهو تصميم يسمح بالتوسع الأفقي ويتيح ترقية أو استبدال أي مكون بشكل مستقل. كما أنها مصممة لتكون مستقلة عن بيئة النشر: إذ تتيح ١٢ نوعًا من الاتصالات استخدام الأداة ذاتها ووصف JSON نفسه لاستهداف جهاز محلي، أو مضيف بعيد عبر SSH، أو بيئة تشغيل Docker أو Kubernetes، أو مثيلات سحابية عبر AWS SSM / Azure Serial Console / GCP OS Login، أو آلات افتراضية عبر Libvirt — نفس الوصف التصريحي، يُنشر أينما وجهته. تدعم الأداة ٢٥ توزيعة Linux تشمل عائلات غربية (Ubuntu، Debian، CentOS، Fedora، AlmaLinux، Rocky، openSUSE)، روسية (ALT، Astra، ROSA)، وصينية (openEuler، openKylin، Deepin)، مع تثبيت غير مراقب عبر preseed/kickstart/cloud-init/autoyast وأتمتة الآلات الافتراضية القائمة على QEMU للاختبار. تشمل الميزات المؤسسية تشفير AES-256-GCM، سياسات كلمات المرور المفروضة ومفاتيح SSH، تهيئة جدار الحماية تلقائيًا لمنافذ البريد (٢٥/٥٨٧/٤٦٥/٩٩٣/٩٩٥)، TLS/SSL مع التحقق من الشهادات وHSTS، تسجيل التدقيق، والتحكم في الوصول المستند إلى الأدوار (RBAC). أما الميزات التشغيلية فتشمل ضبط JVM (G1GC)، ذاكرة التخزين المؤقت Caffeine، تجميع الاتصالات، المقاييس المتوافقة مع Prometheus، التسجيل المنظم، إعادة تحميل الإعدادات دون توقف، وإدارة الأسرار. يبلغ المشروع عن ٤٣٩ اختبارًا بنسبة نجاح ١٠٠٪ وبوابة جودة SonarQube نظيفة. وهي المشروع الرائد لمنظمة Server-Factory.

المحتوى

## لماذا قمنا ببنائه

إعداد خادم بريد آمن وجاهز للإنتاج يعد عمليةً عرضة للأخطاء ومحددة لنظام التشغيل. يلتقط Mail Server Factory هذه الخبرة في نموذج JSON التصريحي بالإضافة إلى محرك تنفيذ، بحيث يمكن إعادة إنتاج مجموعة بريدية صحيحة وآمنة ومعبأة في حاويات Docker على أي هدف مدعوم دون الحاجة إلى خطوات يدوية متتالية.

## لماذا يعد تغييراً جذرياً

إنه ينقل عملية تجهيز خادم البريد من مهمة متخصصة تستغرق أياماً وتتطلب الدقة المطلقة إلى مجرد كتابة تكوين، ثم يجعل هذه العملية قابلة للنقل عبر 12 نوعاً من الاتصالات و25 توزيعة Linux، مع تمكينها تلقائياً بإعدادات أمان مؤسسية افتراضية. النتيجة قابلة للتكرار والتحقق: ينتج نفس JSON دائماً نفس المجموعة الآمنة، ويضمن المشروع الذي حقق 439 اختباراً ناجحاً ونظافة بوابة SonarQube أن المحرك القائم بالعمل يخضع للمساءلة بدلاً من الاعتماد على السمعة فقط.

## ما الجديد في الابتكار

- نموذج JSON التصريحي → تثبيت/تهيئة مفسرة على نظام التشغيل الهدف.
- 12 نوع اتصال (محلي، SSH، Docker، Kubernetes، AWS SSM، Azure، GCP، Libvirt، وغيرها) خلف أداة واحدة.
- دعم لـ 25 توزيعة مع تثبيت غير مراقب (preseed/kickstart/cloud-init/autoyast) وأتمتة QEMU.
- مجموعة حاويات Docker مترابطة بشكل مرن لتمكين التوسع/التحديث المستقل.

## التحديات والحلول

- **تعدد أنظمة التشغيل والتوزيعات:** تم حلها بوصفات خاصة بكل توزيعة، وتكوينات تثبيت غير مراقب، واختبار عبر التوزيعات باستخدام QEMU.
- **الوصول إلى أهداف نشر متعددة:** تم حلها بـ 12 نوع اتصال قابل للتوصيل تحت محرك تثبيت مشترك.
- **الأمان افتراضياً:** تم حلها باستخدام AES-256-GCM، وسياسات مفاتيح/كلمات مرور إلزامية، وقواعد جدار حماية آلية، وTLS/HSTS.
- **الثقة في الصحة:** تم حلها بمجموعة اختبارات مكونة من 439 اختباراً (نسبة نجاح 100%) وبوابة SonarQube النظيفة.

## مجموعة التقنيات (السبب وكيفية الاستخدام)

- **Kotlin** — محرك Factory ومنطق خطوات التثبيت (179 ألف بايت؛ Kotlin 2.0.21).
- **Shell** — نصوص التجهيز، ومديري ISO/QEMU، وأتمتة نظام التشغيل (مهيمن من حيث الحجم).
- **Docker** — بيئة التشغيل لمجموعة البريد المترابطة بشكل مرن.
- **QEMU** — أتمتة الأجهزة الافتراضية للتثبيت والاختبار عبر التوزيعات.
- **JSON** — تنسيق التكوين التصريحي الذي يواجه المستخدم.
- **Gradle 8.14.3 / Java 17** — سلسلة أدوات البناء.
- **Caffeine** — التخزين المؤقت متعدد المناطق؛ **JVM مضبوطة على G1GC** للأداء.
- **مقاييس متوافقة مع Prometheus** — المراقبة؛ جاهزة لـ Grafana/ELK.
- **Sieve** — قواعد تصفية البريد (بصمة صغيرة في إحصائيات اللغة).
