## Defect class

Build-if-missing applied to test fixtures: `_tests/export/self-validate.sh` built the golden PDFs only when a
file was absent, so an edit to `build-fixtures.sh` left the previous recipe's PDFs in place and the harness
validated an outdated recipe.

## Sources consulted

- The item record in `docs/workable_items.db` (description, closure criteria, anchor `_tests/export/self-validate.sh`).
- `_tests/export/self-validate.sh` (rebuild guard and its comment) and `docs/zero-gap/checks/VSC-383.check`.
- Constitution anchors section 11.4.201 and 11.4.240, read by heading.

## Alternatives considered

1. Always rebuild into the run's output directory: always correct, but slower and changes where fixtures live.
2. Rebuild when `build-fixtures.sh` is newer than either PDF (chosen): minimal change, keeps the committed fixtures.
3. Also compare the image generator input: rejected inside the code comment, because in a fresh git checkout that
   file is written after the fixtures and would look newer, forcing a rebuild on every clean clone.

## Why the fix is right

The check is behavioural, not textual: it copies the harness to a scratch directory, plants a stub builder newer
than backdated PDFs, runs the real `self-validate.sh` and requires that the builder was invoked. A guard that only
tested for file existence cannot satisfy it. Residual limit: only the recipe script is compared, not its other inputs.
