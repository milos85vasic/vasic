## Defect class

False-green gate on an unasked remote: `scripts/verify-submodule-remote-sync.sh` compared a gitlink only against the
fetch URL of `origin`. A submodule whose `origin` pushes (`remote.origin.pushurl`) to other repositories could lag at a
push target and still read CURRENT.

## Alternatives considered

1. Probe only the fetch URL (status quo): the defect.
2. Fail whenever a pushurl differs: false reds for in-sync mirrors.
3. Probe each distinct pushurl with the same ref and compare to the gitlink (chosen): LAGS/BEHIND/DIVERGED are findings,
   unreadable is state 2, current is a PASS; credentials in http(s) URLs are masked in messages.

## Why the fix is right

The probe builds a specimen where fetch is at the tip and push lags; a control without the lagging target must be green,
the subject must not be, and the message must name the push target. Live run, reported as observed: rc 1,
`30 CURRENT, 13 DRIFT, 0 UNDETERMINED of 21 owned gitlinks probed`; the drift rows are real (for example submodules/qa is
AHEAD of its remote and three push targets LAG), and no row is state 2, so rc 2 is not raised for readable remotes.
Residual limits: a submodule that is not checked out has no readable pushurl (a NOTE); the live DRIFT is an operator matter
(a push), not a defect of the gate. One earlier author attempt sealed outcome 2 (UNSTABLE, tree moved) and was retried.

current script: stale main + trunk at the gitlink + dangling HEAD gave rc 2 CANNOT VERIFY (no false CURRENT); a single-branch
remote with a dangling HEAD gave rc 0 and named refs/heads/main. Author RED/GREEN re-sealed (chain_seq 321 / 322); the earlier
