## Defect class

A test-suite driver that derives its exit status from the FAIL counter alone reports success when every case was
skipped. Zero assertions executed, rc 0: a vacuous pass (the PASS-over-nothing class of sections 11.4 and 11.4.201).

## Sources consulted

- `scripts/test-setup-agents-wizard.sh`, summary block from `^TOTAL=` to EOF (lines 1523-1561 at the time of reading):
  `EXECUTED=$((PASS+FAIL))`; `EXECUTED -eq 0` gives `VERDICT_RC=2`, a failure gives 1, otherwise 0; the evidence
  banner states "COULD NOT DETERMINE" when nothing executed; `summary.json` carries `skipped`, `executed`, `exit_code`.
- `docs/zero-gap/checks/VSC-377.check` and `probes/vsc-377.sh`: extract the tree's own summary block, run it with planted
  counters (3 pass / 0 fail / 1 skip must be rc 0; 3 / 1 / 0 must be rc 1; 0 / 0 / 7 must be rc 2).
- `docs/zero-gap/CLOSURE.md` (three-valued outcomes: 2 is never a pass) and constitution anchor sections 11.4.6 and 11.4.201.

## Alternatives considered

1. Keep rc 0 and only print a warning on all-skipped: a caller reading the exit status still sees success.
2. Treat all-skipped as rc 1 (failure): accuses the wizard of a defect nobody measured.
3. rc 2 "could not determine" when EXECUTED is zero (chosen): matches the repository's three-valued contract.

## Why the fix is right

SKIP asserts nothing, so the verdict must depend on executed cases, not on the absence of failures. The probe exercises
the real summary block of the tree under test in three directions (control pass, control fail, all-skipped), so a
fix that merely changed the banner without changing the exit status would not satisfy it. Residual limit: the probe
runs the summary block in isolation with planted counters; it does not run the 1500-line suite itself.
