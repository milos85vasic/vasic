## Defect class

A sweep class that refuses every non-regular file as COULD-NOT-INSPECT undercounts its population when a tracked
symlink points at a regular file in the same repository: the content is inspectable through its target, so the
refusal hides nothing real but leaves the population unexplained (838 items, 837 inspected in the register text).

## Alternatives considered

1. Follow every symlink: rejected, it would read out-of-tree or cross-repository content the class must not read.
2. Keep refusing all symlinks and document the gap: leaves the class blind to a real inspectable file.
3. Treat a link as an alias only when `readlink -f` lands on a regular, non-symlink file inside the same base and
   (live mode) the same git repository (chosen). Dangling, out-of-tree and cross-repository links stay refused.

## Why the fix is right

The decision is made on the fully resolved path and repository identity, so a link cannot smuggle in outside
content. The probe asserts both directions in one run: the in-tree alias is not refused and the dangling link still is.
Residual limit: in the fixture mode (corpus mode) the same-repository test is skipped because no repository exists.
