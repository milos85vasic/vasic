## Defect class

A published figure computed from a snapshot artifact that silently goes stale. `scripts/badges/compute_badges.sh`
read the row count of `docs/findings/zero_findings_ledger.jsonl` (written only by
`zero_findings_sweep.sh --write-ledger`) and typed it into the README badge, so the badge could under-state the open
findings against the live tree (the item records 23 shown against 41 live). Class: stale-figure / false-evidence.

## Sources consulted

- `scripts/badges/compute_badges.sh`, `measure_all`, the zero-findings badge branch: it now runs the live sweep when
  `scripts/audit/zero_findings_sweep.sh` exists at the root, extracts `class=TOTAL live=<n>`, and sets the badge to
  `ledger stale <n> vs <live> live` when they differ, or `ledger unverified` when the sweep is present but yields no
  TOTAL; only otherwise does it fall through to the count branches.
- `docs/zero-gap/checks/VSC-348.check` and `probes/vsc-348.sh`: a throwaway shared clone, a control ledger freshly
  regenerated by the clone's own sweep (must not be flagged), then a planted ledger with one row removed (must be flagged).
- Constitution anchor section 11.4.259(C) as quoted in the code comment (provenance must not contradict the colour).

## Alternatives considered

1. Regenerate the ledger inside the badge script: the badge computation would write a tracked artifact as a side effect.
2. Add a freshness timestamp comparison: a timestamp says nothing about whether rows match the tree.
3. Compare the ledger row count with the live sweep TOTAL and refuse to show a mismatch or an unconfirmed snapshot (chosen).

## Why the fix is right

The badge no longer trusts a snapshot it cannot confirm: a mismatch is shown as RED "stale" and an undeterminable sweep is
shown as RED "unverified", so neither presents a number as fact. The probe covers both directions (control not flagged,
planted flagged) so an always-stale or never-stale implementation fails it. Residual limit: the comparison is by row count;
a ledger with the same count but different rows would not be flagged. The probe takes about two minutes because it runs
the live sweep several times.
