## Defect class

The exempt registry row for `scripts/zero-gap-evidence.sh` carried a `fact_sha256` of that single script only. The
script's behaviour is also defined by `_tools/zero-gap-chain/argvpolicy.go` (the argv policy it calls), so an edit
there was not seen as drift and the exemption could outlive the code it describes.

## Measurable target

"a planted edit of argvpolicy.go is reported as drift (1 of 1 mutation caught)". The probe builds a sandbox holding the
tree's own exempt row verbatim, the files that row can cover, and a conforming dummy check row; it requires a clean
control (no FACT DRIFT) and then FACT DRIFT after appending one comment line to the sandbox copy of argvpolicy.go. It
therefore measures the target and refuses to pass if the control already drifts. RED on pre-fix (outcome 1), GREEN on
the working tree (outcome 0). Note the target is one planted mutation on one file, which is what the item states; the
verifier's own M15 suite additionally covers edit, added file, deleted file, vanished literal path and an excluded
test file staying quiet, with the control digest computed by plain `sha256sum` rather than the verifier's helper.

## Alternatives considered

1. Add a second exempt row per file: rows multiply and each can drift separately.
2. Hash a git tree object: ties the registry to git state and to the whole directory including tests.
3. A backwards-compatible `set:<digest>=<specs>` field (chosen): legacy single-file hashes keep working; a new,
   removed, renamed or edited covered file moves the digest; a literal path matching nothing is a failure.

## Limits and recall cost (stated honestly)

The set is only as complete as the spec list a human writes: the row names the adapter, `zero-gap-lib.sh`, the module's
non-test Go files and `go.mod`. A file outside that list (for example the evidence recorder in the constitution
submodule the adapter invokes, which is upstream and not hashed here) is still invisible to this row. Test files are
excluded by design, so a behaviour change made only in a `*_test.go` file is not drift. The glob is basename-only.
