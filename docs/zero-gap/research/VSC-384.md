## Defect class

Governance drift in a tool catalogue: the missing-toolchain class derived findings for four tools (`docs_chain`,
`ifconfig`, `lumen`, `shellcheck`) that scripts probe only as a fallback or an optional leg. Absence of such a tool is not
a rc-2 condition, but the catalogue (`docs/zero-gap/toolchains.tsv`) carried no row stating that role, so each sweep
reported a derived finding for something that is by design allowed to be absent.

## Sources consulted

- The item record in `docs/workable_items.db`.
- `docs/zero-gap/toolchains.tsv` (the four rows added, each with role, probe, evidence path) and
  `scripts/zero-gap-class-missing-toolchain.sh` (how a catalogued FALLBACK/OPTIONAL role suppresses the finding).
- `docs/zero-gap/checks/VSC-384.check` and `VSC-384.probe.sh`.
- Live run of the class on this tree: the four tools print "catalogued FALLBACK/OPTIONAL ... inspected and not reported".

## Alternatives considered

1. Install the four tools: an operator action, and it would hide rather than state the role.
2. Exempt the tools inside the class script: weakens the detector for every future tool.
3. Catalogue the role per tool in the data file (chosen): the detector stays unchanged; a tool with no role still reports.

## Why the fix is right

The probe is behavioural: it runs the real class and requires no `derived:<tool>` finding for the four tools, with a rc-2
guard if the class cannot run. RED on the pre-fix ref was outcome 1, GREEN outcome 0. Residual limit: the class still
reports an unrelated docs-drift finding (tesseract recorded as missing in a document); that is a different item.
