## Defect class

A detector that walks a declared population and reports "nothing found" while the population was empty or partly
unreachable. In `scripts/audit/zero_findings_sweep.sh`, `detect_uncatalogued` skipped a declared scanroot that was
absent on disk (`continue`) and returned 0 when no `*.sh` file was examined at all: an empty or uninspected population
scored as a clean one (vacuous pass, sections 11.4.6 and 11.4.201).

## Alternatives considered

1. Treat an absent scanroot as a finding (rc 1): a missing directory is a could-not-inspect fact, not a defect in a file.
2. Silently skip but log: downstream consumers read only the verdict and see "complete".
3. Name the skipped roots, record them in the detector's recall statement and force the class UNDETERMINED, rc 2 (chosen).

## Why the fix is right

The verdict now depends on whether the population was actually examined. The probe runs the sweep of the tree under
test against fixtures for both empty-population shapes and a control that must raise neither signal, so a detector
that always signals, or never signals, fails it. Residual limit: the probe asserts the stderr signal text, not the
sweep's overall exit code for those fixtures; M15 and M16 inside the sweep's own `--prove-failure` assert rc 2.
