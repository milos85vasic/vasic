## 1. What the candidate is, and what it is not

The QA candidate is an **integration** of everything that has been built so far, including branches that are
still in review or fix rounds. It exists so that you can use every flow and report what is wrong.

* It is **not a release**, **not main**, and **not reviewed as a whole**. Expect defects. Finding them is the
  purpose.
* It lives on its own branch, `qa-candidate`, in its own git worktree. Nothing is ever merged from it into
  `main` or `int-0.0.3`, and nothing is pushed anywhere by the scripts (`scripts/qa-candidate.sh` contains no
  push and refuses any push-shaped argument).
* The branch is rebuilt **by script** (`scripts/qa-candidate.sh`) from the committed tips of the stream
  branches. The record of what went in, at which commit, and how any conflict was resolved is
  `evidence/qa-candidate/MANIFEST.tsv` inside the candidate branch.
* The instance you test is a **plain server process on its own port** with a **copy** of the live data. It
  shares nothing writable with the live service.

## 2. Start, stop, reset

All commands run from the umbrella checkout (`~/Projects/vasic`).

| Task | Command | Notes |
|---|---|---|
| First start (everything) | `bash scripts/qa-candidate-up.sh up` | Builds the server and the Angular bundle from the candidate worktree, copies the data, applies the research-library re-ingest to the copy, provisions the seven accounts, starts the server and waits until it is healthy. The first run takes several minutes (the Angular build waits for the host's load governor). |
| Is it running? | `bash scripts/qa-candidate-up.sh status` | Exit 0 up and answering, 1 down. Prints the URL. |
| Health check | `bash scripts/qa-candidate-up.sh health` | `/api/health`, then a sign-in as each administrator and as `student1`. Prints status codes only, never a password. |
| Stop | `bash scripts/qa-candidate-up.sh down` | Signals only the process this script started (verified by its executable). |
| Reset the QA data | `bash scripts/qa-candidate-up.sh reset` | Stops the server, wipes **only the QA copy** (`data/`), copies the live data again, re-applies the research re-ingest, re-provisions the accounts. Students go back to the initial password. The binaries and the credentials file are kept. |
| Rebuild binaries and bundle after the candidate branch moved | `bash scripts/qa-candidate-up.sh down && bash scripts/qa-candidate-up.sh build && bash scripts/qa-candidate-up.sh up` | `build` always recompiles the Go binaries; it recompiles the bundle only when no bundle exists in the worktree (delete `platform/frontend/dist` in the worktree to force it). |
| LAN access | `QA_CANDIDATE_BIND=0.0.0.0 bash scripts/qa-candidate-up.sh up` | Off by default. The instance serves a recording of an identifiable third party; binding beyond loopback exposes it to the network. The script says so before binding. |

**If the instance goes down** (host restart, session ended, someone ran `down`): `bash scripts/qa-candidate-up.sh up` is idempotent and starts it again with the same data. To restart automatically run `setsid nohup bash scripts/qa-candidate-up.sh watch >/dev/null 2>&1 &` (checks `/api/health` every 30 s, runs `up` when it fails; stop it by killing that one pid).

Individual stages can be run on their own: `build`, `data`, `research`, `accounts`. Environment knobs
(`QA_CANDIDATE_QA_ROOT`, `QA_CANDIDATE_PORT`, `QA_CANDIDATE_BIND`, `QA_CANDIDATE_CREDS`, `QA_CANDIDATE_OLLAMA`,
`QA_CANDIDATE_SKIP_WEB`, `QA_CANDIDATE_NG_WRAPPER`) are documented in the header of the script
(`bash scripts/qa-candidate-up.sh --help`).

## 4. Accounts and credentials

Seven accounts exist in the QA auth store (spec 023): administrators (professors) **`milosvasic`** and **`rami`**;
students **`student1`** .. **`student5`**.

* The passwords are **random 20-character values generated for this instance**. They are in
  **`~/.cache/claude-tmp/qa/credentials.env`** (mode 0600). The file has three entries:
  `WORKSHOP_ADMIN_PASSWORD_MILOSVASIC`, `WORKSHOP_ADMIN_PASSWORD_RAMI`, `WORKSHOP_STUDENT_INITIAL_PASSWORD`
  (one initial password shared by the five students). Open the file yourself; the scripts never print a value.
* The operator's own weak initial student password is not known to these scripts and is not used.
* **Students start flagged "must change password":** after the first sign-in the server allows only `/account`
  (`403 password_change_required` everywhere else). That is a flow to test (spec 023); after the change the student
  signs in with the new password. `reset` returns students to the initial password.
* Sign-in is rate limited (5 attempts per minute per account); a "too many login attempts" answer is the
  limiter working, wait a minute.

## 6. Rebuilding the candidate after branches advance

```bash
bash scripts/qa-candidate.sh            # merges only the tips that are not yet contained; idempotent; rc 0 / 1 / 2
bash scripts/qa-candidate.sh --status   # read-only: what a run would do
bash scripts/qa-candidate.sh --prove-failure   # paired proof of the script's own guarantees
```

Exit **0** every listed branch is merged and the candidate builds; **1** a branch is missing, conflicted, or was rejected
for breaking the Go build (it is aborted and recorded in the manifest; the candidate stays buildable); **2** could not
determine (git missing, dirty candidate worktree, forbidden argument). A conflict is resolved once by hand in the
candidate worktree (union; commit subject ending `[conflict-resolved]`); `git rerere` is enabled there so the same
resolution replays. A branch that cannot be merged without breaking the build is parked by adding a reason in the third
column of its row in `scripts/qa-candidate.branches.tsv`. After the branch moved, restart the instance with
`down`, `build`, `up` (section 2).
