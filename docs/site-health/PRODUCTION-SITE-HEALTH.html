pages.yml exists specifically because the default recursive checkout fails on a broken nested gitlink in milosvasic.ru/Upstreamable. That failure is not hypothetical — the legacy builder errored four times before the workflow was introduced:

GitHub’s API returns only the generic string Page build failed. — the underlying runner log is not exposed through this endpoint, so the specific error text is UNVERIFIED beyond that message. Operator guidance: submodules: false in pages.yml must not be flipped to true and pages.yml must not be deleted (which would fall back to the legacy builder that fails). Upstreamable is excluded from the Jekyll build anyway — milosvasic.ru/_config.yml line 45:

  - Upstreams
