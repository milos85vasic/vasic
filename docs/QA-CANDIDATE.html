1. What the candidate is, and what it is not

The QA candidate is an integration of everything that has been built so far, including branches that are still in review or fix rounds. It exists so that you can use every flow and report what is wrong.

  • It is not a release, not main, and not reviewed as a whole. Expect defects. Finding them is the purpose.
  • It lives on its own branch, qa-candidate, in its own git worktree. Nothing is ever merged from it into main or int-0.0.3, and nothing is pushed anywhere by the scripts (scripts/qa-candidate.sh contains no push and refuses any push-shaped argument).
  • The branch is rebuilt by script (scripts/qa-candidate.sh) from the committed tips of the stream branches. The record of what went in, at which commit, and how any conflict was resolved is evidence/qa-candidate/MANIFEST.tsv inside the candidate branch.
  • The instance you test is a plain server process on its own port with a copy of the live data. It shares nothing writable with the live service.

Seven accounts exist in the QA auth store (spec 023): administrators (professors) milosvasic and rami; students student1 .. student5.

Open the file yourself; the scripts never print a value.
  • The operator's own weak initial student password is not known to these scripts and is not used.
  • Students start flagged "must change password": after the first sign-in the server allows only /account (403 password_change_required everywhere else). That is a flow to test (spec 023); after the change the student signs in with the new password. reset returns students to the initial password.
  • Sign-in is rate limited (5 attempts per minute per account); a "too many login attempts" answer is the limiter working, wait a minute.

6. Rebuilding the candidate after branches advance

bash scripts/qa-candidate.sh            # merges only the tips that are not yet contained; idempotent; rc 0 / 1 / 2
bash scripts/qa-candidate.sh --status   # read-only: what a run would do
bash scripts/qa-candidate.sh --prove-failure   # paired proof of the script's own guarantees

Exit 0 every listed branch is merged and the candidate builds; 1 a branch is missing, conflicted, or was rejected for breaking the Go build (it is aborted and recorded in the manifest; the candidate stays buildable); 2 could not determine (git missing, dirty candidate worktree, forbidden argument). A conflict is resolved once by hand in the candidate worktree (union; commit subject ending [conflict-resolved]); git rerere is enabled there so the same resolution replays. A branch that cannot be merged without breaking the build is parked by adding a reason in the third column of its row in scripts/qa-candidate.branches.tsv. After the branch moved, restart the instance with down, build, up (section 2).
