Mail-Server-Factory

अपना मेल सर्वर बॉस की तरह चलाएँ — इसे JSON में लिखें, कहीं भी तैनात करें।

सारांश

Mail Server Factory एक उत्पादन-तैयार, स्वचालित मेल-सर्वर प्रोविजनिंग टूल है। उपयोगकर्ता एक सरल JSON कॉन्फ़िगरेशन लिखता है; फैक्ट्री उसे पढ़कर लक्षित ऑपरेटिंग सिस्टम पर सभी इंस्टॉलेशन और आरंभिक सेटअप कर देती है, जिससे 12 कनेक्शन प्रकारों पर Docker-आधारित, ढीले-ढाले जुड़ाव वाला मेल स्टैक तैनात हो जाता है।

संक्षिप्त विवरण

एक Kotlin/Shell टूल जो JSON विवरण को पूरी तरह इंस्टॉल्ड, डॉकराइज़्ड मेल सर्वर में बदल देता है। यह 12 कनेक्शन प्रकारों (SSH, Docker, Kubernetes, AWS SSM, Azure, GCP, Libvirt और अन्य) को सपोर्ट करता है, साथ ही एक पूर्ण सुरक्षा ढाँचा, 25 Linux वितरण और 439 सफल परीक्षणों के साथ आता है।

विस्तृत विवरण

एक वास्तविक, सुरक्षित मेल सर्वर स्थापित करना सिस्टम एडमिनिस्ट्रेशन का एक क्लासिक अनुष्ठान है — और साथ ही सबसे अधिक निराशाजनक अनुभवों में से एक। पोस्टफिक्स, डोवकोट, TLS प्रमाणपत्र, DNS रिकॉर्ड, फ़ायरवॉल नियम और प्रति-वितरण विशेषताएँ — सब कुछ बिल्कुल सही ढंग से संरेखित होना चाहिए, और एक भी गलत निर्देश चुपचाप मेल रिजेक्ट करवा सकता है या ओपन रिले बना सकता है। Mail Server Factory इस पूरे कठिन-से-अर्जित, त्रुटि-प्रवण विशेषज्ञता को सॉफ़्टवेयर में समाहित कर देता है। किसी अपरिचित ऑपरेटिंग सिस्टम पर हर घटक को हाथ से कॉन्फ़िगर करने के बजाय, अंतिम उपयोगकर्ता वांछित परिणाम को एक सरल JSON दस्तावेज़ के रूप में लिखता है; फैक्ट्री उस JSON को पढ़कर लक्षित ऑपरेटिंग सिस्टम पर आवश्यक इंस्टॉलेशन और आरंभिक चरणों को क्रियान्वित करती है, जिससे Docker पर चलने वाला एक मेल स्टैक खड़ा हो जाता है — जहाँ हर घटक ढीले-ढाले जुड़ाव के साथ डिज़ाइन किया गया है। यह डिज़ाइन स्टैक को क्षैतिज रूप से स्केलेबल बनाए रखता है और किसी भी एकल घटक को अलग से अपग्रेड या बदला जा सकता है। साथ ही, यह जानबूझकर पहुँच-अज्ञेयवादी है: 12 कनेक्शन प्रकारों के माध्यम से एक ही टूल और एक ही JSON स्थानीय मशीन, SSH के ज़रिए दूरस्थ होस्ट, Docker या Kubernetes रनटाइम, AWS SSM / Azure सीरियल कंसोल / GCP OS लॉगिन के माध्यम से क्लाउड इंस्टेंस, या Libvirt के ज़रिए वर्चुअल मशीनों को लक्षित कर सकता है — एक ही घोषणात्मक विवरण, जहाँ भी आप इसे निर्देशित करें। यह पश्चिमी (उबुन्टू, डेबियन, सेंटओएस, फेडोरा, अल्माLinux, रॉकी, ओपनस्यूज़), रूसी (ALT, एस्ट्रा, रोसा) और चीनी (ओपनयूलर, ओपनकाइलिन, दीपिन) परिवारों के 25 Linux वितरणों को सपोर्ट करता है, जिसमें प्रीसीड/किकस्टार्ट/क्लाउड-इनिट/ऑटोयास्ट के ज़रिए अनअटेंडेड इंस्टॉलेशन और परीक्षण के लिए QEMU-आधारित वीएम ऑटोमेशन शामिल है।

एंटरप्राइज़ सुविधाएँ व्यापक हैं: AES-256-GCM एन्क्रिप्शन, अनिवार्य पासवर्ड और SSH-की नीतियाँ, मेल पोर्ट्स (25/587/465/993/995) के लिए स्वचालित फ़ायरवॉल कॉन्फ़िगरेशन, TLS/SSL प्रमाणपत्र सत्यापन और HSTS के साथ सुरक्षा, ऑडिट लॉगिंग और RBAC। परिचालन सुविधाओं में JVM ट्यूनिंग (G1GC), कैफ़ीन कैशिंग, कनेक्शन पूलिंग, Prometheus-संगत मेट्रिक्स, संरचित लॉगिंग, हॉट-रीलोडिंग कॉन्फ़िगरेशन और सीक्रेट्स प्रबंधन शामिल हैं। प्रोजेक्ट में 439 परीक्षण 100% सफलता दर के साथ पास हैं और SonarQube गुणवत्ता गेट साफ़ है। यह सर्वर-फैक्ट्री संगठन का प्रमुख प्रोजेक्ट है।

सामग्री

हमने इसे क्यों बनाया

एक सुरक्षित, प्रोडक्शन मेल सर्वर सेटअप करना बेहद त्रुटिप्रवण और ऑपरेटिंग सिस्टम-विशिष्ट होता है। Mail Server Factory उस विशेषज्ञता को एक घोषणात्मक JSON मॉडल और एक निष्पादन इंजन में समाहित करता है, ताकि बिना मैन्युअल चरण-दर-चरण काम के किसी भी समर्थित लक्ष्य पर एक सही, सुरक्षित और डॉकराइज़्ड मेल स्टैक को पुनः निर्मित किया जा सके।

यह क्यों गेम-चेंजर है

यह मेल-सर्वर प्रोविज़निंग को एक विशेषज्ञ, दिनों तक चलने वाले, बिल्कुल सही करने के कठिन कार्य से घटाकर केवल कॉन्फ़िगरेशन लिखने का काम बना देता है — फिर उस काम को 12 कनेक्शन प्रकारों और 25 Linux वितरणों पर पोर्टेबल बनाता है, और बॉक्स से ही एंटरप्राइज़ सुरक्षा डिफ़ॉल्ट्स के साथ मज़बूत करता है। परिणाम पुनरुत्पादन योग्य और सत्यापन योग्य है: हर बार वही JSON वही सुरक्षित स्टैक देता है, और प्रोजेक्ट के 439 पास होने वाले टेस्ट और स्वच्छ SonarQube गेट का मतलब है कि काम करने वाला इंजन खुद जवाबदेह है, न कि केवल प्रतिष्ठा पर भरोसा किया जाता है।

क्या है नवाचारी

  • घोषणात्मक JSON → लक्ष्य ऑपरेटिंग सिस्टम पर व्याख्यायित इंस्टॉलेशन/इनिशियलाइज़ेशन।
  • एक ही टूल के पीछे 12 कनेक्शन प्रकार (लोकल, SSH, Docker, Kubernetes, AWS SSM, Azure, GCP, Libvirt, और अन्य)।
  • 25 वितरणों का समर्थन, जिसमें अनअटेंडेड इंस्टॉल (preseed/kickstart/cloud-init/autoyast) और QEMU ऑटोमेशन शामिल है।
  • स्वतंत्र स्केलिंग/अपग्रेड के लिए ढीले-ढाले ढंग से जुड़ा डॉकराइज़्ड स्टैक।

चुनौतियाँ और समाधान

  • ऑपरेटिंग सिस्टम/वितरण विविधता: प्रति-वितरण रेसिपी, अनअटेंडेड-इंस्टॉल कॉन्फ़िगरेशन और QEMU-आधारित क्रॉस-डिस्ट्रो टेस्टिंग से हल।
  • कई डिप्लॉयमेंट लक्ष्यों तक पहुँच: 12 प्लग करने योग्य कनेक्शन प्रकारों को एक सामान्य इंस्टॉलेशन इंजन के तहत लाकर हल।
  • डिफ़ॉल्ट सुरक्षा: AES-256-GCM, अनिवार्य कुंजी/पासवर्ड नीतियाँ, स्वचालित फ़ायरवॉल नियम और TLS/HSTS से हल।
  • सही होने पर भरोसा: 439 टेस्ट के सूट (100% पास) और स्वच्छ SonarQube गेट से हल।

तकनीकी स्टैक (क्यों + कैसे)

  • Kotlin — फैक्ट्री इंजन और इंस्टॉलेशन-चरण तर्क (179K बाइट्स; Kotlin 2.0.21)।
  • Shell — प्रोविज़निंग स्क्रिप्ट, ISO/QEMU मैनेजर और OS ऑटोमेशन (बाइट्स के हिसाब से प्रमुख)।
  • Docker — डिप्लॉय किए गए, ढीले-ढाले ढंग से जुड़े मेल स्टैक के लिए रनटाइम।
  • QEMU — क्रॉस-डिस्ट्रीब्यूशन इंस्टॉलेशन और टेस्टिंग के लिए VM ऑटोमेशन।
  • JSON — उपयोगकर्ता के लिए घोषणात्मक कॉन्फ़िगरेशन प्रारूप।
  • Gradle 8.14.3 / Java 17 — बिल्ड टूलचेन।
  • Caffeine — मल्टी-रीजन कैशिंग; G1GC-ट्यून्ड JVM प्रदर्शन के लिए।
  • Prometheus-संगत मेट्रिक्स — मॉनिटरिंग; Grafana/ELK-तैयार।
  • Sieve — मेल फ़िल्टरिंग नियम (भाषा आँकड़ों में छोटा पदचिह्न)।
