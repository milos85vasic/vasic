## PRODUCT FAMILY NOTES

These orgs form one tightly-coupled, submodule-driven engineering ecosystem authored by the same owner (`milos85vasic` / package roots `dev.helix.*` and `digital.vasic.*`). The architecture is "constitution + many decoupled reusable submodules consumed by a few large product apps."

**Governance core (the spine):**
- **HelixConstitution** is the universal rulebook included as a Git submodule by every project (AGENTS.md / CLAUDE.md / QWEN.md, CONST-* clauses, a ~142-repo `submodules-catalogue.md`). It is what makes the family coherent. The recurring "anti-bluff," "no-fakes," "100% test-type coverage," and "submodules-as-equal-codebase / decoupling" themes seen across HelixAgent, HelixQA, LLMOrchestrator, and helix_cluster all trace back to it.

**Flagship product apps (the large repos):**
- **HelixAgent** — the AI ensemble LLM service; the central brain that the AI/agent tooling plugs into ("AI debate ensemble").
- **HelixCode** — distributed AI coding-agent platform.
- **HelixTranslate** — universal translation/ebook toolkit + real-time monitoring.
- **Helix-Track/Core** — the JIRA-alternative issue tracker (its own product line with many clients).
- **HelixPlay** — self-hostable cloud-gaming platform (46 submodules).
- **helix_cluster (Helix Cluster OS)** — distributed OS / scheduler that can host the inference and compute workloads.
- **helix_ota (Helix OTA)** — universal OTA update system (control plane + clients).
- **Helix-Flow/Platform** — unified AI-inference platform (the org has only this one repo; positioned as the inference/serving layer).

**Shared/reusable libraries (small repos, consumed as submodules by the apps above):**
- **LLMProvider** (40+ provider adapters), **LLMOrchestrator** (headless CLI-agent management), **HelixLLM** (local model), **HelixMemory** (Mem0+Cognee+Letta memory engine for HelixAgent), **HelixSpecifier** (spec-driven-dev fusion for HelixAgent), **DebateOrchestrator** (multi-agent debate library), **DagOrchestrator** + **PipelineRuntime** (dataflow/DAG runtimes), **VisionEngine** (CV/LLM vision for UI), **HelixGitpx** (git proxy), **HelixBuilder** (AI build pipeline).
- **QA stack:** **helixqa** (anti-bluff QA orchestrator) + **DocProcessor** (feature-map extraction for QA).
- **OTA submodules:** the six `ota-*` repos (`ota-protocol`, `ota-rollout-engine`, `ota-artifact-validator`, `ota-update-engine-bridge`, `ota-telemetry-schema`, `ota-android-agent`) are the decomposed pieces of **helix_ota**.

**Helix-Track product line (the issue tracker + its clients):**
- **Core** is the backend microservice. Around it sit per-platform **clients** — `iOS-Client`, `Android-Client`, `Desktop-Client`, `Web-Client`, `Aurora-Client`, `Harmony-OS-Client` — plus `Website`, `Website-Theme-Jekyll`, `Screensaver`, `Propriatery` (proprietary components), `Legacy-Project` (archived predecessor), and `Everything` (umbrella/aggregator meta-repo). Most clients are private.

**Server-Factory (infrastructure-provisioning sibling family):**
- A separate, mostly-fork-based Kotlin/Shell org for **server provisioning automation**. **Mail-Server-Factory** is the flagship product; **Core-Framework** is the shared engine; **Web-Service-Factory**, **SonarQube-Factory**, **Caching-Proxy-Factory** are per-service "factories"; **Stack/Software/Docker-Definitions** are declarative configuration packs; **Utils / Qemu-Utils / Parallels-Utils** are tooling. It predates the Helix work (2022–2023 timestamps on several repos) and is more of an adjacent toolchain than part of the AI product core.

**Demos / games:** `Helix-Game-Demo`, `Stake-Tetris`, `Helix-Game-1` (all archived/private) are Stake-Engine game experiments, related to the gaming theme (HelixPlay, Helix-Game-Demo SDK) but not part of the production product line.

**Summary of relationships:** HelixConstitution = shared law → consumed by everything; a small set of large Go product apps (HelixAgent, HelixCode, HelixTranslate, HelixPlay, Helix-Track/Core, helix_cluster, helix_ota, Helix-Flow/Platform) compose dozens of small, deliberately-decoupled reusable submodule libraries. Helix-Track is its own product (tracker + many clients), and Server-Factory is an older, adjacent provisioning-automation toolchain.
