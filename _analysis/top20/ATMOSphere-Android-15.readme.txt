# ATMOSphere Android 15 (Orange Pi 5 Max)

**Revision:** 3
**Last modified:** 2026-05-20T08:30:00Z
**Status:** Always-sync per Constitution §11.4.59 (HTML + PDF refreshed via `scripts/testing/sync_readme_export.sh`)

Custom Android 15 (API level 35, Baklava) firmware for **Orange Pi 5 Max (RK3588)**, built from AOSP source with **135+ applied fixes** and optimizations. Repository optimized for GitHub hosting (~18GB compressed from 303GB).

**This project exclusively targets Orange Pi 5 Max. No other devices or build targets are supported.**

## Governance

This project inherits the **HelixConstitution** at `constitution/` (submodule).
[`constitution/Constitution.md`](constitution/Constitution.md) is the canonical authority for all universal rules
(anti-bluff covenant §11.4, no-guessing mandate §11.4.6, host-session safety §12, data safety §9,
mutation-paired gates §1.1, etc.). Project-specific rules extend it via [`CLAUDE.md`](CLAUDE.md)
and [`AGENTS.md`](AGENTS.md) at this repo's root.

When this repo's CLAUDE.md/AGENTS.md disagrees with the constitution submodule, the constitution wins
(per §11.4.35 canonical-root inheritance clarity).

## Quick Start

```bash
# Clone the repository
git clone --recurse-submodules git@github.com:vasic-digital/Android-15-AOSP.git
cd Android-15-AOSP

# Extract compressed toolchains and binaries (~40 directories, ~50GB)
./scripts/setup.sh --parallel 8

# Build (MUST use official build script — see docs/scripts/build.md)
rm -f rockdev/*.img && rm -f RKTools/linux/Linux_Pack_Firmware/rockdev/*.img
bash scripts/build.sh --skip-pull --skip-tests --skip-ota

# Containerized build (Constitution §12.9 — bypasses user.slice oomd)
bash scripts/build_containerized.sh --skip-pull --skip-tests --skip-ota

# Flash (device in MASKROM mode: hold RECOVERY → USB → power → 5s → release)
sudo bash scripts/enable_flashing_capabilities.sh
bash scripts/flash.sh --quick
sudo bash scripts/enable_flashing_capabilities.sh --restore
```

## Repository Structure

This repository uses a hybrid storage approach to work within GitHub's constraints:

| Category | Storage Method | Size |
|----------|---------------|------|
| Source code | Direct git | ~1GB |
| Large toolchains | Compressed archives | ~17GB (compressed from ~54GB) |
| Build outputs | Excluded (.gitignore) | N/A |
| Repo metadata | Excluded (.gitignore) | N/A |

**Migration Statistics:**
- Original AOSP size: 303GB
- Excluded (.repo + out): 211GB
- Compressed directories: 40
- Total repository size: ~18GB
- Compression ratio: ~3:1

### Compressed Directories

The following directories are stored as multi-part `.tar.xz` archives in `.compressed/` and extracted by `setup.sh`:

- **prebuilts/clang/** — Clang/LLVM toolchains (~14GB)
- **prebuilts/rust/** — Rust toolchains (~14GB)
- **prebuilts/sdk/** — Android SDK versions (~5GB)
- **prebuilts/abi-dumps/** — ABI snapshots (~5.5GB)
- **external/deqp/** — Graphics test suite (~1.6GB)
- **device/google/*-kernels/** — Pre-built device kernels (~8GB)
- And more — see `scripts/config/directories.conf`

## Development Workflow

```bash
# Make changes, then commit and push using the MANDATORY script:
bash scripts/commit_all.sh "Description of changes"

# NEVER use git add/commit/push directly — commit_all.sh handles
# compression, staging, committing, and pushing to ALL remotes.
```

Per Constitution §11.4.42 iteration discipline, work proceeds in priority-ordered cycles:
select TOP+MIDDLE critical items → batch implementation per §11.4.9 (source-side batching with §11.4.4
four-layer coverage) → smoke-test gate (<30 min) → §11.4.40 full-system retest (12-48 h) → release-ready.

```bash
bash scripts/testing/meta_test_false_positive_proof.sh

bash scripts/testing/sync_issues_docs.sh
```

Per §11.4.49 dual-approach + §11.4.48 UI-driven mandates, every feature test ships in TWO variants
(UI-driven + Intent/Broadcast-driven). Per §11.4.50 deterministic consistency, every PASS is run
N=3 (10 for cycle-validation) and asserted identical across iterations.

Per §11.4.52 autonomous-validation mandate, every user-facing feature MUST have at least one
autonomous validation path (operator-attended tests are SUPPLEMENTARY, never PRIMARY).

## Troubleshooting

### Setup fails with "Checksum verification failed"

Archive may be corrupted during transfer. Re-extract:

```bash
rm -rf path/to/extracted/dir
./scripts/setup.sh --extract archive-name
```

### Build fails with missing prebuilt

```bash
./scripts/setup.sh --status
```

### Build OOM-kills the host session

Constitution §12.6/§12.7/§12.8/§12.9 guard the host against this. Use containerized build:

```bash
bash scripts/build_containerized.sh --skip-pull --skip-tests --skip-ota
```

### Out of disk space during extraction

Estimated space needed: ~150GB. Free up space or use external storage.

### Device boots to recovery (no display)

See [`docs/orange-pi-5-max/TROUBLESHOOTING.md`](docs/orange-pi-5-max/TROUBLESHOOTING.md).

## Features

### Hardware
- RK3588 octa-core CPU with CPU2 exclusive audio isolation
- Mali-G610 GPU with OpenGL ES 3.2
- Dual HDMI output (HDMI-A-1 / HDMI-A-2) — TV + touch screen routing per Fix #80
- NVMe SSD storage + SPI NOR flash bootloader
- RTL8125 2.5GbE Ethernet (Fix #79)
- Wired touch panel (WCH.cn USB2IIC_CTP_CONTROL) IDC + 90° rotation (Fix #130 / #133)

### Audio
- ES8388 analog codec with always-both-outputs routing (Fix #104) and kernel DAPM mixer fix (Fix #105)
- Bluetooth A2DP with 400ms buffer chain, CPU2 IRQ affinity, UART flow control (Fix #63 / #72)
- USB audio and USB microphone support
- FFmpeg Codec2 AC-3 / E-AC-3 / DTS / DTS-HD / TrueHD / MLP decoders (Fix #106 / #112)
- 5.1 / 7.1 multichannel LPCM HDMI output (Fix #112) — see `docs/guides/MULTICHANNEL_AUDIO_USER_GUIDE.md`

### Networking
- WiFi (**Synaptics SYN43711 / Broadcom BCM43711**, WiFi 6) via `bcmdhd.ko`
- WiFi roaming daemon **v14.0** with safe 5GHz band steering, BTCOEXMODE preemption, wpa_cli roam (Fix #59 / #72 / #77)
- BSSID blocklist tuning (Fix #37)
- TCP buffer tuning: rmem/wmem 8MB, BBR congestion control (Fix #26)
- Captive portal disable for RU region (Fix #113)

### Video & DRM
- HW video codecs: 8 decoders + 3 encoders (c2.rk Codec 2.0; HW AVC disabled per Fix #94)
- SW codecs (c2.android.*) for 4K AVC, 8K HEVC/VP9/AV1 (Fix #107)
- Widevine L3 dual-variant DRM: KonstaKANG A15 arm64 CDM + Rockchip A13 32-bit fallback (Fix #114)
- Universal HDMI2 video enforcing — framework MediaCodec.configure() hook + NDK hook redirects video to secondary display (Fix #88 / #99 / #107 / #111)
- Subtitle routing to secondary display (Fix #115)

### Apps (60+ prebuilt apps)
- Google Apps (MindTheGapps, 21 APKs, toggle-able)
- ATMOSphere forks: SmartTube, Lampa, TorrServe, VLC, MPV (5 platform-signed forks; see `docs/guides/*_INTEGRATION.md`)
- Streaming: Netflix, Disney+, Prime Video, HBO Max, Hulu (L3 SD), Kinopoisk, RuTube, Wink, Premier, IVI (60+ apps total)
- Local: Kodi, AIMP, HiByMusic, Vimeo, Telegram, ...

### System
- Linux flashing via flash.sh (upgrade_tool with DDR retry, MASKROM auto-detect)
- **135+ applied fixes** for Android 15 on RK3588 (see CLAUDE.md "Applied Fixes Reference")
- Comprehensive test suite per §11.4 anti-bluff covenant:
  - **1698+ pre-build tests** (CM-* gates with paired mutations)
  - **post-build image gates** (sparse images, LPM metadata, vendor libs, multichannel codec registrant)
  - **45+ post-flash test suites** with 4-phase verification (boot → reboot → factory reset → reboot)
  - **dual-approach** per §11.4.49 (UI-driven + Intent/Broadcast-driven variants for every feature)
  - **autonomous-validation** per §11.4.52 (no test requires operator presence to PASS)
- Zero power saving (always-on appliance) — see CLAUDE.md "MANDATORY POWER SAVING CONSTRAINTS"
- Per-display UI density override (Fix #131, current 295 dpi on display 0)
- Idle-dim daemon (Fix #132, 1s poll, Option A backlight soft-dim preserves Fix #65 always-on)

### Known Limitations

- Camera disabled (no hardware on Orange Pi 5 Max)
- SELinux in permissive mode (userdebug builds)
- Widevine L1 keybox NOT shipped (TA is in-tree; L1 enablement requires castlabs/third-party licensing — see `docs/guides/CASTLABS_L1_FIRST_CONTACT.md`)
- Some streaming apps geo-restricted in certain regions (e.g. YouTube in RU needs VPN) — see CLAUDE.md "Video app geo-restriction" rule
