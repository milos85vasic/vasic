# HelixPlay

**GPU 기기로 클라우드 게이밍 기기를 구축하세요.**

## 요약

HelixPlay는 자체 호스팅 가능한 클라우드 게이밍 플랫폼으로, GPU가 탑재된 기기를 원격 스트리밍 호스트로 변환하여 데스크톱, 모바일, TV, 브라우저 클라이언트에 콘솔급 게임 플레이를 제공합니다. 46개의 하위 모듈로 구성된 Go 기반 모노레포로 구축되었으며, 파트너를 위한 화이트 라벨링이 가능합니다.

## 간략 설명

HelixPlay는 자체 호스팅 가능하고 오픈 소스이며 화이트 라벨링이 가능한 클라우드 게이밍 플랫폼입니다. GPU가 탑재된 기기를 원격 스트리밍 호스트로 변환하여 WebRTC/QUIC를 통해 데스크톱, 모바일, TV, 브라우저 클라이언트에 콘솔급 게임 플레이를 제공합니다. Go 코어를 기반으로 Wails/Flutter/Angular 클라이언트 스택으로 구성되어 있습니다.

## 상세 설명

HelixPlay는 46개의 Git 하위 모듈로 구성된 Go 기반 모노레포로 구축된 클라우드 게이밍 플랫폼입니다. 사용자가 이미 소유한 게이밍 PC를 스트리밍 호스트로 변환하여 데스크톱, 모바일, TV, 브라우저 클라이언트에 콘솔급 경험을 제공합니다. 자체 호스팅이 가능하며 오픈 소스이고 파트너를 위한 화이트 라벨링이 지원됩니다. 핵심 메시지는 명확합니다. '당신의 하드웨어, 당신의 서비스, 당신의 브랜드, 중간에 제3자의 클라우드는 없습니다.’

이 플랫폼의 핵심 설계는 트리플 스택 클라이언트 통합입니다. 이는 모든 곳에서 효과를 발휘하는 과감한 아키텍처적 결정입니다. Wails 데스크톱 앱, Flutter 모바일/TV 앱, Angular 웹 클라이언트는 모두 *단일* Go 코어를 기반으로 하며, 브라우저용 WASM으로 컴파일되어 동작이 한 번 작성되면 모든 플랫폼에서 공유됩니다. 세 가지로 분기되는 대신 하나의 코드로 모든 환경에서 일관성을 유지합니다. 그 아래에는 실시간 미디어 경로가 존재합니다: 캡처 → 인코딩 → 패킷화 → 전송 → 디코딩 → 렌더링. 플랫폼 네이티브 캡처(DXGI / ScreenCaptureKit / PipeWire)와 하드웨어 인코더(NVENC / QSV / AMF / VideoToolbox)를 활용하여 GPU 기기가 무거운 작업을 처리하도록 설계되었으며, WebRTC(Pion v4), QUIC(quic-go), 그리고 지연 시간을 최소화하기 위해 설계된 커스텀 UDP 데이터그램을 통해 전송됩니다. 백엔드 코어는 세션, 테넌트, 카탈로그, 인증을 관리하며, 호스트 에이전트는 엣지에서 캡처, 인코딩, 전송을 담당합니다. mDNS/랜데뷰를 통해 클라이언트가 호스트를 자동으로 발견할 수 있도록 연결됩니다.

HelixPlay는 화이트 라벨 SaaS를 염두에 두고 처음부터 설계되었습니다. 테넌트별 테마, 카탈로그 필터링, OAuth2, 결제 시스템을 지원하여 파트너가 완전히 브랜딩된 서비스를 구축할 수 있습니다. 또한 모든 서비스, 데이터베이스, 빌드, 테스트, 스캔이 컨테이너 내에서 실행되도록 설계되어 플랫폼 전체를 재현 가능하게 배포하고 검증할 수 있습니다. Helix 제품군과 마찬가지로, 이 플랫폼은 '녹색 테스트’가 실제 최종 사용자가 사용할 수 있는 동작을 보장하는 것을 목표로 하는 '블러핑 방지 원칙’에 따라 운영됩니다. 단순한 모의 테스트 통과가 아닙니다.

## 개발 배경

상용 클라우드 게이밍은 폐쇄적이고 중앙 집중적이며 임대형입니다. HelixPlay는 GPU 기기를 소유한 누구나 자신의 스트리밍 호스트를 운영할 수 있도록 개발되었습니다. 오픈 소스, 자체 호스팅, 화이트 라벨링이 가능하여 제3자 서비스에 의존하지 않아도 됩니다.

## 왜 혁신적인 게임 체인저인가

이 기술은 상용 서비스들이 분리해 놓은 세 가지 요소를 하나로 통합합니다. 바로 여러분이 제어하는 하드웨어에서의 셀프 호스팅, 세 가지 클라이언트 스택을 동시에 구동하는 단일 Go 코어, 그리고 화이트 레이블 다중 테넌시입니다. 그 결과 파트너는 타사의 클라우드에 의존해 용량을 재판매하거나 그 한계에 묶이는 대신, *자체* GPU에서 완전 브랜딩된 클라우드 게임 서비스를 출시할 수 있게 됩니다. 즉, 경험과 사용자, 수익 구조를 온전히 소유하게 되는 것입니다.

## 혁신적인 요소

- **트리플 스택 클라이언트 컨버전스** — Wails, Flutter, Angular가 하나의 Go 코어(브라우저에서는 WASM)를 공유하여 데스크톱, 모바일, TV, 웹이 세 개의 따로 노는 구현체가 아닌 단일한 구현체를 공유합니다.
- **셀프 호스팅 가능 화이트 레이블 SaaS** — 테넌트별 테마, 카탈로그 필터링, OAuth2, 빌링 기능이 기본 내장되어 있어 플랫폼이 데모가 아닌 브랜딩 가능한 제품으로 제공됩니다.
- **최신 저지연 전송 기술** — WebRTC(Pion), QUIC, 커스텀 UDP와 플랫폼별 하드웨어 인코더 선택(NVENC/QSV/AMF/VideoToolbox)을 결합해 편의성보다 응답성을 우선시합니다.
- **46개 모듈로 분리된 아키텍처** — 모든 구성 요소가 깔끔하게 분리된 컨테이너 네이티브 구조: 각 서비스, 데이터베이스, 빌드, 테스트, 스캔이 컨테이너에서 실행됩니다.

## 가장 큰 기술적 도전 과제와 해결 방법

- **이종 하드웨어 간 저지연 스트리밍.** 모든 OS와 GPU는 캡처와 인코딩 방식을 다르게 제공하며, 지연 시간은 용납되지 않습니다. 이를 플랫폼 인식 캡처/인코딩 경로(DXGI/ScreenCaptureKit/PipeWire에서 NVENC/QSV/AMF/VideoToolbox로 전달)로 해결했으며, WebRTC/QUIC/UDP를 통해 각 기기가 픽셀에 가장 빠르게 접근하는 네이티브 경로를 사용하도록 했습니다.
- **데스크톱, 모바일, TV, 웹에서 작동하는 단일 제품.** 트리플 스택 클라이언트(Wails, Flutter, Angular)가 브라우저용 WASM으로 컴파일된 단일 Go 코어를 공유하도록 하여, 한 번의 수정이나 기능 추가가 네 가지 플랫폼에 즉시 반영되도록 했습니다.
- **다중 테넌트 화이트 레이블 운영.** 테넌트별 테마, 카탈로그 필터링, OAuth2, 빌링 기능을 백엔드 코어에 직접 내장하여 테넌트 격리와 브랜딩이 플랫폼의 기본 기능으로 구현되도록 했습니다.

## 기술 스택

- **Go(1.26.2 루트 / 1.25+ 서브모듈)** — 공유 코어 백엔드 및 호스트 에이전트. 네이티브 바이너리와 WASM으로 컴파일되는 단일 언어로, 단일 코어 멀티 클라이언트 설계를 가능하게 합니다.
- **Wails v2** — 데스크톱 클라이언트로, Go 코어를 임베디드 웹뷰에 바인딩하여 데스크톱 앱이 코어 로직을 재구현하지 않고 직접 재사용할 수 있게 합니다.
- **Flutter 3.29+** — 모바일/TV 클라이언트로, FFI를 통해 Go 코어에 접근하여 별도의 백엔드 없이 스마트폰과 TV에서 네이티브 UI를 제공합니다.
- **Angular 17+** — 웹 클라이언트로, 동일한 Go 코어를 WASM으로 컴파일하여 브라우저를 단순한 축소판이 아닌 1급 플랫폼으로 활용합니다.
- **WebRTC/Pion v4, QUIC/quic-go, 커스텀 UDP** — 세 가지 실시간 전송 프로토콜로, 네트워크와 클라이언트 환경에 따라 최저 지연 경로를 선택할 수 있습니다.
- **하드웨어 인코더(NVENC/QSV/AMF/VideoToolbox) 및 플랫폼 캡처(DXGI/ScreenCaptureKit/PipeWire)** — GPU 가속 캡처 및 인코딩 경로로, 플랫폼별로 최적의 인코딩 방식을 선택해 CPU 병목 현상을 방지합니다.
- **컨테이너(Docker/Podman)** — 모든 서비스, 데이터베이스, 빌드, 테스트, 스캔이 컨테이너화되어 시스템 전체를 재현 가능하게 배포하고 검증할 수 있습니다.
- **mDNS/랜데부** — 제로 컨피그 호스트 검색으로 클라이언트가 네트워크상에서 스트리밍 호스트를 자동으로 찾아 연결됩니다.
