# HelixMemory

**AI 에이전트를 위한 하나의 기억 뇌 — 네 가지 최첨단 엔진의 융합**

## 요약

HelixMemory는 네 가지 선도적인 기억 시스템(Mem0, Cognee, Letta, Graphiti)을 단일한 인지 기억 엔진으로 통합하는 Go SDK입니다. 이 엔진은 네 가지 시스템을 병렬로 검색하고 그 결과를 융합하여 AI 애플리케이션에 네 개의 분리된 기억 계층 대신 하나의 지속 가능하고 중복 제거된 재순위화된 기억 계층을 제공합니다.

## 간략 설명

HelixMemory는 Mem0, Cognee, Letta, Graphiti를 AI 애플리케이션을 위한 하나의 통합 인지 기억 엔진으로 융합하는 Go SDK입니다. 이 시스템은 쓰기 작업을 지능적으로 라우팅하고, 모든 백엔드를 병렬로 검색하며, 세 단계(수집-중복 제거-재순위화) 파이프라인을 통해 결과를 융합합니다.

## 상세 설명

HelixMemory는 AI 애플리케이션을 위한 통합 인지 기억 엔진으로, Go SDK(모듈 `digital.vasic.helixmemory`, Go 1.25+ 버전)로 제공됩니다. 이 시스템의 기본 전제는 어떤 단일 기억 프로젝트도 모든 면에서 최적일 수 없다는 것입니다. 따라서 처음부터 기억을 재구현하여 한 프로젝트의 한계를 물려받기보다는, 네 가지 최첨단 시스템을 조율하여 각자의 강점을 최대한 활용하도록 설계되었습니다. 구체적으로, Mem0는 동적 사실 추출과 선호도 관리를, Cognee는 ECL 파이프라인을 통해 구축된 의미론적 지식 그래프를, Letta는 편집 가능한 기억 블록과 수면 시간 연산을 지원하는 상태 기반 에이전트 런타임을, Graphiti는 시간이 지남에 따라 사실의 변화를 추론하는 양방향 시간 지식 그래프를 담당합니다.

이 네 가지 독립적인 저장소를 하나의 뇌로 통합하는 것이 바로 융합 엔진의 역할입니다. 쓰기 경로에서는 들어오는 모든 기억이 내용에 따라 분류되어 가장 적합한 백엔드로 라우팅됩니다. 읽기 경로에서는 쿼리가 모든 백엔드로 병렬 전송되며, 검색된 결과는 세 단계(수집, 중복 제거, 교차 소스 재순위화) 융합 파이프라인으로 유입됩니다. 이를 통해 호출자는 네 개의 소음 섞인 중복 결과 집합이 아닌, 하나의 깔끔하고 순위가 매겨진 답변만을 받게 됩니다. 각 백엔드는 서킷 브레이커로 감싸져 있어, 한 엔진이 다운되더라도 브레이커가 작동하여 나머지 백엔드가 계속 서비스를 제공할 수 있으며, 전체 기억 계층이 함께 다운되는 일은 없습니다. 이 엔진은 `MemoryStore` 인터페이스를 직접 구현하고 있어 기존의 단순한 기억 제공자를 대체하는 데 아무런 구조 변경 없이 바로 적용할 수 있으며, Prometheus 메트릭을 통해 라우팅과 융합의 내부 동작을 완전히 관찰할 수 있습니다.

HelixMemory는 HelixAgent, 즉 더 넓은 Helix AI 앙상블의 기억 계층으로 개발되었으며, 이 시스템은 가족 특유의 '허세 없는 테스트' 원칙을 기억 영역으로 확장 적용합니다. 프로세스 내 챌린지 러너는 실제 운영 코드 경로(라우팅, 융합, 변환기, 서킷 브레이커)를 실행하는 동시에, 페어드 뮤테이션 래퍼는 의도적으로 불변성을 깨뜨려 로직이 깨졌을 때 테스트가 실제로 실패하는지 검증합니다. 따라서 테스트 스위트가 그린 라이트를 보이면 그 의미가 명확해집니다.

## 개발 배경

콘텐츠

AI 에이전트는 장기적이고 고품질의 메모리를 필요로 하지만, 현재 생태계는 파편화되어 있습니다. 각 메모리 프로젝트(Mem0, Cognee, Letta, Graphiti)는 한 가지 기능에 강점을 지니지만 다른 부분에서는 취약합니다. HelixMemory는 HelixAgent를 위해 이들의 강점을 결합하면서도 특정 시스템에 종속되지 않는 단일한 메모리 레이어를 제공하기 위해 설계되었습니다.

## 왜 혁신적인가

더 이상 선택의 딜레마에 갇히지 않아도 됩니다. 보통 동일한 자리를 놓고 경쟁하는 네 가지 메모리 시스템이 하나의 인터페이스 뒤에서 상호 보완적인 백엔드로 작동하게 됩니다. 덕분에 애플리케이션은 동적 사실 추출, 의미론적 지식 그래프, 상태 기반 에이전트 메모리, 이중 시간 추론을 *동시에* 활용할 수 있으며, 중복 제거와 교차 소스 재랭킹은 자동으로 처리됩니다. 이전에는 실현 불가능했던 "어떤 메모리 엔진을 채택해야 할까?"라는 질문은 이제 허위의 딜레마가 됩니다. HelixMemory는 하나의 `MemoryStore` 인터페이스 뒤에서 모든 엔진의 강점을 한꺼번에 누릴 수 있게 해주며, 특정 엔진의 약점이나 종속성 문제에서도 자유롭습니다.

## 혁신적인 요소

- **다중 백엔드 퓨전**(수집 → 중복 제거 → 교차 소스 재랭킹): 단일 스토어에 의존하지 않고, 여러 소스에서 수집한 결과를 하나의 랭킹된 결과 세트로 반환합니다.
- **지능형 쓰기 라우팅**: 각 메모리의 내용을 분석해 가장 적합한 엔진으로 전송하여, 데이터가 제자리에 저장되도록 합니다.
- **안정적인 성능 저하**: 백엔드별 회로 차단기를 통해 장애가 발생한 엔진을 격리하고, 나머지 시스템은 정상적으로 작동하도록 유지합니다.
- **유휴 시간 컴퓨팅 통합**(Letta 활용): 쿼리 시점뿐 아니라 유휴 시간에 메모리를 재구성하여 효율성을 높입니다.
- **허위 검증 방지**: 실제 운영 코드에 대한 챌린지 러너와 변이 래퍼를 결합해, 불변 조건이 깨지면 반드시 테스트가 실패하도록 보장함으로써, 테스트 게이트가 단순한 동어반복이 아님을 증명합니다.

## 가장 큰 기술적 도전 과제와 해결 방법

- **네 가지 이질적인 백엔드를 하나의 일관된 결과 세트로 통합하기** — 각 엔진은 고유한 형식으로 메모리를 반환하며, 단순 병합 시 중복과 비호환 랭킹 문제가 발생합니다. 이를 해결하기 위해 타입 기반 퓨전 엔진을 도입해 여러 소스에서 수집한 데이터를 중복 제거하고, 공통 기준으로 재랭킹하며, 병합 과정에서 결과가 누락되거나 중복 집계되지 않도록 테스트에서 퓨전 카운트 불변 조건을 검증합니다.
- **백엔드 장애 시에도 시스템 유지하기** — 하나의 메모리 엔진이 접근 불가능해져도 전체 레이어가 중단되지 않아야 합니다. 이를 위해 백엔드별 회로 차단기를 구현해 장애 발생 시 닫힘 → 열림(장애 임계값 초과 후) → 반열림(타임아웃 후) 상태 머신을 적용하고, 장애가 발생한 백엔드를 격리한 뒤 정상 작동하는 백엔드에서 계속 서비스를 제공합니다.
- **메모리 로직의 실제 작동 여부 검증하기** — 테스트가 통과해도 실제 작동 여부는 불확실할 수 있습니다. 이를 해결하기 위해 실제 운영 코드(라우팅, 퓨전, 변환기, 회로 차단기)를 구동하는 인프로세스 챌린지 러너와 불변 조건을 뒤집는 변이 래퍼를 도입해, 테스트가 반드시 실패하도록 강제함으로써 검증 게이트가 단순한 동어반복이 아님을 입증합니다.

## 기술 스택

- **Go (1.25+)** — 단일 SDK 및 런타임. 네 개의 백엔드에 걸친 병렬 읽기 팬아웃이 동시성 문제이기 때문에 선택되었으며, Go의 고루틴 덕분에 비용 효율적으로 처리할 수 있고, 인터페이스 타입을 통해 전체 시스템에 하나의 깔끔한 경계면(`MemoryStore`)을 제공하여 호출자가 의존할 수 있도록 합니다.
- **Mem0** — 동적 사실 추출 및 선호도 관리 백엔드. 사용자의 실제 선호도나 드러난 사실에 관한 메모리 조각을 처리합니다.
- **Cognee** — ECL 파이프라인을 기반으로 구축된 의미론적 지식 그래프 백엔드. 평면적인 사실이 아닌 구조화된 관련 지식을 저장합니다.
- **Letta** — 편집 가능한 메모리 블록과 슬립 타임 컴퓨팅을 지원하는 상태 유지 에이전트 런타임 백엔드. 메모리가 라이브 에이전트 상태로 지속되어야 하며 유휴 시간 동안 통합되어야 하는 경우에 사용됩니다.
- **Graphiti** — 이중 시간 지식 그래프 백엔드. 현재의 값뿐만 아니라 사실과 관계의 시간적 변화에 대한 추론에 사용됩니다.
- **PostgreSQL + Neo4j + Redis** — 백엔드가 실제로 실행되는 데이터 저장소. `make infra-start`를 통해 실제 통합 테스트를 위해 구축되어, 모의 객체가 아닌 실시간 인프라에서 테스트 스위트가 동작합니다.
- **Prometheus** — 퓨전 파이프라인을 통해 연결된 메트릭 및 관측 가능성 도구. 라우팅과 퓨전 동작이 프로덕션에서 측정 가능하도록 하며, 블랙박스가 아닙니다.
- **i18n 번역 경계면** — 네임스페이스(`helixmemory_`)가 지정된 문자열 레이어. 향후 사용자 인터페이스 레이어를 현지화할 때 코어 시스템을 재구성하지 않아도 되도록 유지합니다.
