# HelixSkills

**CLI AI агенттері үшін конституцияға негізделген, басқарылатын дағдылар жүйесі.**

## Қысқаша мазмұны

HelixSkills — бұл CLI AI агенттері үшін дағдылар жүйесі. Ол Helix Constitution модулін ішкі модуль ретінде қамтиды, сондықтан әмбебап басқару ережелері шартсыз қолданылады. Жүйе агент дағдыларын, MCP құралдық серверлерін, Claude Code плагиндерін және қайта пайдаланылатын қозғалтқыштарды тіркеуге болатын, құжатталған каталог түрінде ұсынады.

## Қысқаша сипаттама

HelixSkills — бұл CLI AI агенттері үшін дағдылар жүйесі. Ол Helix Constitution модулін ішкі модуль ретінде енгізеді, сондықтан барлық әмбебап ережелер қолданылады, содан кейін тіркеуге болатын дағдыларды (әрекет-префикс, медиа-тексеруші, көпжолды, сессияны синхрондау, жұмыс элементінің өмірлік циклі және т.б.), екі MCP құралдық серверін, екі Claude Code плагиндерін және қайта пайдаланылатын қозғалтқыштарды ұсынады.

## Толық сипаттама

HelixSkills (`skills` репозиторийі, Apache-2.0 лицензиясы) — бұл CLI AI агенттері үшін дағдылар жүйесі. Ол әдеттегі тәртіпті әдейі кері айналдырады: басқару бірінші орында, мүмкіндіктер екінші орында. Ол Helix Constitution модулін `constitution/` ішкі модулі ретінде қамтиды, сондықтан `constitution/CLAUDE.md` және `constitution/Constitution.md` файлдарындағы әмбебап ережелер шартсыз қолданылады — бұл агенттің құрметтейтін дәстүрі емес, жобаның кодтық ағашына физикалық түрде енгізілген ережелер жинағы. HelixSkills қабылдаған агент конституциядан бас тарта алмайды; ережелер кодпен бірге жүреді.

Көптеген "дағдылар фреймворктары" абстракциялармен жұмыс істесе, HelixSkills нақты, тіркеуге болатын инвентарды ұсынады, оны көрсетіп, орнатуға болады. Жеті конституциялық дағды `register.sh` арқылы орнатылады: action-prefix-system, media-validator, multitrack, reporting-workable-items, scheduled-work-queue, session-sync және workable-item-lifecycle — орташадан жоғары деңгейге дейінгі ауқымды қамтитын жиынтық, ол тәртіптелген әрекеттерді атаудан бастап медиа-тексеруге және жұмыс бірлігінің толық өмірлік цикліне дейінгі барлық нәрсені қамтиды. Қосымша жобалау сатысындағы дағдылар (Android шолуы, Java/Kotlin тілі, Linux ОЖ) индекстеліп, белсендірілуге дайын тұр. Екі MCP құралдық сервері (media-validator, scheduled-work) осы дағдыларды Model Context Protocol арқылы агенттерге ұсынады, ал екі Claude Code плагині (helix, scheduled-work) бірдей мүмкіндіктерді тікелей агенттің орындау ортасына енгізеді — бір дағдылар жиынтығы агенттермен әртүрлі беттер арқылы байланысады.

Тіркеу каталогының астында төрт тереңдігі бірдей қайта пайдаланылатын қозғалтқыш орналасқан — continuum (іске асырылған), сондай-ақ session_orchestrator, token_optimizer және clickup_sync (жобалануда) — дағдылардың бірдей құбырларды қайта ойлап табуын болдырмайтын ортақ механизмдер. Token_optimizer жалғыз өзі vasic-digital экосистемасының пакеттеріне (TOON, Embeddings, VectorDB, Normalize, conversation) және HelixDevelopment-дың LLMProvider-ына дейінгі тәуелділіктердің анық графикасын жариялайды, сондықтан оның репозиторийлер арасындағы байланыстары тексерілетін, анық түрде көрсетілген. Барлығының айналасында тәртіптелген құжаттама айналып жүреді: дағдылар каталогы, автоматты түрде жасалған дағдылар графикасының индексі, әр репозиторий үшін жеке беттер және әлі жасалмаған нәрселерді атап көрсететін ашық "Ақаулар мен қатерлер" тізімі. Бүкіл жүйе GitHub, GitLab, GitFlic және GitVerse платформаларында айналымда тұрады, бұл оның төзімділігін және аймақтық қол жетімділігін қамтамасыз етеді.

Мазмұны

## Неліктен құрастырдық

CLI және AI агенттеріне тұрақты, басқарылатын және қайта пайдаланылатын мүмкіндіктер қажет – әрқайсысы ережелерді қайта ойлап табатын жеке скрипттер емес. HelixSkills агенттерге ортақ конституцияға негізделген, тіркелетін дайын дағдылар жиынтығын беру үшін құрастырылды. Бұл әрбір агент пен жобадағы мінез-құлық біркелкі және тексерілетін болып қалады.

## Неліктен бұл өзгерістің бастауы

Агенттің мүмкіндіктері құрылым бойынша тасымалданатын және ережелерге сәйкес келетін болып, тәртіпке негізделмейді. Әрбір дағды – конституциялық кіші модульмен қолдау алған, басқарылатын, нұсқаланатын және орнатылатын бірлік. Сондықтан агент дағдыны тіркеген сәтте ол канондық ережелер жиынтығын да міндетті түрде қабылдайды, ауытқуға мүмкіндік қалмайды. Бұл бұрын іске асыру мүмкін болмаған нәрсені ашады: мүмкіндікті бір агенттен немесе жобадан екіншісіне ауыстырып, ол сол басқару жүйесіне байланыстырылған күйінде келетінін білу. Сонымен қатар, әрқайсысы ережелерді қайта ойлап табатын жеке жапсырма скрипттердің орнына, стандартты интерфейстер (MCP серверлері және Claude Code плагиндері) арқылы ұсынылады.

## Жаңашылдығы

- **Constitution кіші модуль ретінде**: әмбебап басқару ережелері көшірілмей, мұраға алынады – ағашқа қосылып, әрбір тұтынушы агент бірдей канондық ережелер жиынтығына байланыстырылады. Жаңартулар бір ғана шынайы көзден келіп, ондаған ескірген көшірмелердің орнына қолданылады.
- **Өзін-өзі тіркеуші бірліктер ретінде ұсынылатын дағдылар** (`register.sh`) және автоматты түрде жасалатын дағдылар графінің индексіне тігіледі. Бұл каталог іздеуге қолжетімді болып, орнатылған нәрсемен үнемі үйлесімді болып қалады.
- **Көп интерфейсті ұсыну**: бірдей дағдылар жиынтығы MCP құрал серверлері және Claude Code плагиндері арқылы агенттерге жеткізіледі – бір рет жазып, агент пайдаланатын кез келген ортаға сөйлейді.
- **Экосистема бойынша ортақ пайдаланылатын тереңдік-1 қозғалтқыштар** (continuum, token_optimizer, session_orchestrator, clickup_sync). Әрқайсысы ашық және тексерілетін кросс-репозиторийлік тәуелділіктерді көрсетеді, жасырын байланыстардың орнына.

## Ең үлкен техникалық қиындықтар және оларды қалай шештік

- **Көптеген дағдылар мен агенттер арасындағы агент мінез-құлқының тұрақтылығын және ережелерге сәйкестігін сақтау** – әрбір дағды үшін басқаруды қайта іске асыру уақыт өте келе ауытқуға әкеледі. Бұл мәселе Helix Constitution-ті кіші модуль ретінде қосу арқылы шешілді. Осылайша, `constitution/CLAUDE.md` және `constitution/Constitution.md` құжаттарындағы ережелер шартсыз қолданылып, бір ғана жоғарыдағы көзден жаңартылады, көшіріліп, ескіртілмейді.
- **Өсетін дағдылар жиынтығын орнатуға және табуға болатындай ету** – егер каталогтағы нәрселерді ешкім таба алмаса немесе орната алмаса, ол пайдасыз. Бұл мәселе әрбір дағды үшін `register.sh` тіркеу арқылы шешілді. Ол орнату кезінде әрбір дағдыны қосады, сонымен қатар автоматты түрде жасалатын INDEX дағдылар графі және әрбір репозиторий үшін жеке құжаттамалар бар. Бұл іздеудің нақты жағдайға үнемі сәйкес келуін қамтамасыз етеді.
- **Әртүрлі орталарда жұмыс істейтін агенттерге жету** – бір мүмкіндікті әрбір хост үшін қайта құру керек емес. Бұл мәселе бір дағдылар жиынтығын MCP құрал серверлерінің анықтамалары (`constitution/mcp/` астында) және Claude Code плагиндері (`constitution/plugins/` астында) арқылы ұсыну арқылы шешілді. Бір ғана іске асыру әртүрлі интерфейстер арқылы қол жетімді болады.

## Технологиялық стек

- **Shell (негізгі тіл)** — агент орналасқан кез келген жерде іске қосылу мен тіркелу құралдарын жұмыс істету үшін таңдалды, алдымен іске қосуға арналған орындау ортасы қажет емес; ол `register.sh` және `install_upstreams` скрипттерін қуаттайды, алғашқы қадамдағы тәуелділіктерді жоққа шығарып, тасымалдауға ыңғайлы етеді.
- **Git субмодульдері** — басқаруды көшірусіз мұраға алу үшін таңдалды: Helix Constitution `constitution/` деректемесінде тікелей сілтеме ретінде орналастырылған, сондықтан ережелерді жаңарту бір көрсеткіш арқылы таралады, көшіріліп қойылып ұмытылып кетпейді.
- **Model Context Protocol (MCP)** — агенттер үшін стандартты, орындау ортасына тәуелсіз құралдық интерфейс ретінде таңдалды; `constitution/mcp/` деректемесінде екі MCP сервері (media-validator, scheduled-work) құрал ретінде шақырылатын дағдыларды ұсынады.
- **Claude кодтық плагиндері** — агенттің орындау ортасына қосымша байланыстырусыз дағдыларды тікелей енгізу үшін таңдалды; екі плагин (helix, scheduled-work) `constitution/plugins/` деректемесінде орналасқан, бұл MCP бетінің басқа хост үшін көшірмесі болып табылады.
- **Қайта пайдаланылатын қозғалтқыштар (continuum, token_optimizer, session_orchestrator, clickup_sync)** — жеке дағдылардан бөлінген ортақ механизмдерді жобалары арасында қайта пайдалану үшін таңдалды; мысалы, token_optimizer vasic-digital пакеттерімен (TOON, Embeddings, VectorDB, Normalize, conversation) және HelixDevelopment-тің LLMProvider-імен кодты көшірусіз, жарияланған тәуелділіктер арқылы байланыстырылған.
- **Көпхосттық Git айналуы (GitHub, GitLab, GitFlic, GitVerse)** — бір хосттың істен шығуы немесе аймақтық блоктау кезінде қол жетімділікті үзуге жол бермеу үшін таңдалды; бір дерекқор төрт платформада бірдей тірі ұсталады, төзімділік пен қолжетімділік үшін.

## Жағдай және ашықтық ескертпелері

- **Жағдайы: бета-нұсқа.** Жеті конституциялық дағды, екі MCP сервері және екі плагин жеткізілген; жобаланған дағдылар индекстеліп, іске қосылуға дайын, ал төрт тереңдік-1 қозғалтқыштың үшеуі (session_orchestrator, token_optimizer, clickup_sync) әлі жобалану сатысында.
- README файлы жобаны `helix_skills` деп атайды; ресми GitHub жолы — `HelixDevelopment/skills`. README файлындағы табылған мәселелер саны өзін-өзі есептеу нәтижесі болып табылады.

**Басымдық деңгейі:** Helix-негізгі.
