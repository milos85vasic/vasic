# HelixTranslate

**Тексерілген модельді кітаптарды аудару — адалдық жобаланған, ешқашан үнсіз резервтік нұсқаға көшпейді.**

## Қысқаша мазмұны

HelixTranslate — Go негізіндегі жоғары өнімді электрондық кітаптарды аудару платформасы. Ол 100-нан астам тілдер арасында кітаптарды тексерілген LLM провайдерлері арқылы аударады, нақты уақыттағы WebSocket мониторингімен және үнсіз резервтік нұсқаға көшпеу саясатымен жұмыс істейді. Мұндай саясат сәтсіздіктерді ашық түрде көрсетеді, ешқашан бейхабар түрде сапасын төмендетпейді.

## Қысқаша сипаттама

Go негізіндегі әмбебап электрондық кітаптарды аудару құралы. FB2, EPUB, TXT, HTML, PDF және DOCX форматтарын 100-нан астам тілге аударады. Тексерілген ең мықты LLM модельдерін (LLMsVerifier көпір арқылы) пайдаланады, REST/HTTP-3 және gRPC API-ларымен, таратылған өңдеу жүйесімен және нақты уақыттағы WebSocket мониторингілік тақтасымен жабдықталған.

## Толық сипаттама

HelixTranslate — Go негізіндегі кәсіпорын деңгейіндегі жүйе. Ол кітаптарды тілдер арасында аудару үшін LLM провайдерлерін пайдаланады. Бұл жүйе абзацтар немесе үзінділерді емес, кітаптың басынан аяғына дейінгі толық мәтінді аударады. Көптеген электрондық кітап форматтарын (FB2, EPUB, TXT, HTML, PDF, DOCX) талдайды және қайта құрастырады, 100-нан астам тілді автоматты түрде анықтайды, сондай-ақ CLI құралдары мен API серверлерін (REST HTTP/3 арқылы, gRPC және WebSocket оқиғалар ағыны) ұсынады. Бұл жүйе терминалдағы жұмыс ағымына да, сервис торына да бірдей сәйкес келеді.

Оның айқын ерекшелігі — *модельді қалай таңдауы*. Провайдерді қатаң түрде белгілеп, оның әрқашан жұмыс істей беретініне үміттену орнына, HelixTranslate барлық модельдерді таңдау билігін LLMsVerifier көпірге (`pkg/bridge`) тапсырады. Ол ең мықты *тексерілген* API модельді таңдап, анықталған, бағалау бойынша реттелген резервтік тізбек қайтарады. Модельдің жарамдылығы жауапкершілік, код, мүмкіндіктердің байлығы және сенімділік көрсеткіштері бойынша салмақталған бағалау арқылы анықталады. Демек, сіздің аударманы орындайтын модель өз орнын дәлелдеп, жұмыс істейтінін көрсетіп алған, конфигурациялық файлда көрінгені үшін емес.

Мәні жағынан, жүйе кодта тікелей "үнсіз резервтік нұсқаға көшпеу" талабын жүзеге асырады: егер провайдердің API кілті жоқ болса немесе оператор қолжетімсіз провайдерді сұраса, жүйе адал қате қайтарады, ешқашан бейхабар түрде провайдерді ауыстырмайды немесе жергілікті орындау ортасына көшіп, барлығы жақсы екендігіне әрекет жасамайды. Бұл ереже арнайы құрылыс алдындағы тексеру арқылы және мутациялық тестпен бекітілген. Жергілікті орындау орталары (Ollama, llama.cpp) әдейі әдепкі жолдан алынып тасталған, бұл тексерілмеген әлсіз модель ешқашан тексерілген модельдің орнына үнсіз түрде тұрып қалмауы үшін жасалған.

Аудару ядросының айналасында нақты уақыттағы WebSocket мониторинг жүйесі орналасқан: аударма CLI типтелген оқиғаларды мониторинг серверіне жібереді, ол веб-тақтада тікелей көрсетіледі, ал қашықтағы SSH жұмысшылары жүктемені таратып өңдейді. Жүйеге көп кезеңді өңдеу, сапа талдауының дайындық кезеңі, аудармаларды кешіру (ұзақ мәтіндер үшін шығынды бақылау мақсатында), көруге негізделген сапалық тексеру қосылған. Бүкіл платформа адалдыққа негізделген инженерлік конституцияға бағынады: тесттер нақты, пайдаланушыға көрінетін нәтижелерді дәлелдеуі керек, ал мутациялық тестсіз жасыл белгілер ештеңені дәлелдемейді.

Мазмұны

## Неге құрастырдық

Кітап сияқты ұзақ мәтіндерді сенімді және *адал* аудару үшін — "сапасы төмен болса да бар" аударманы ешқашан жібермеу үшін. Жобаның негізгі қағидасы: жоқ немесе тексерілмеген аударма қатты және айқын қате болуы керек, ал модель таңдауы әрқашан нақты тексерілген провайдерге бағытталуы тиіс, ешқашан алдын ала белгіленген болжамға немесе үнсіз жергілікті резервтік нұсқаға ауыспауы керек.

## Неге бұл өзгерістің бастамасы

LLM аударма құбырларының көпшілігі үнсіз істен шығады — олар әлсіз модельге тыныш ауысады, жергілікті орындау ортасына түседі немесе толық емес нәтиже шығарады, ал сынақ жинағы жасыл түспен жанып тұрады да, ешкім сападағы күрт құлдырауды байқамайды. HelixTranslate осы бүкіл істен шығу режимін құрылымдық түрде мүмкін етпейді: модель таңдауы тексеру арқылы бақыланады, резервтік тізбек анықталған және толық ашық, ал "кілт жоқ / тексерілген модель жоқ" жағдайы үнсіз шартсыз қатеге әкеледі, емес "бәрібір" деген көзқарасқа. Бұл жалғыз жобалау шешімі "осы аударма шынымен қабілетті, тексерілген модельде орындалды ма?" деген сұрақты тексеру мүмкін емес үміттен жүйенің өз тарапынан кепілдік берілетін кепілдікке айналдырады.

## Қандай жаңалықтар бар

- **Тексеру арқылы бақыланатын модель маршруттауы** LLMsVerifier көпір арқылы жүзеге асырылады — ең мықты *тексерілген* модель автоматты түрде таңдалады, сондықтан операторлар мақсатты көрсетеді, провайдер атауларын емес, және ешқашан тоқтап қалуы мүмкін провайдерді қолмен таңдамайды.
- **Үнсіз резервтік ауысуға тыйым салу кепілдігі кодта жүзеге асырылған** — төрт анық маршруттау тармағы (макет / анық тексеруші / анық провайдер / көпір әдепкісі), олардың әрқайсысы үнсіз ауысудың орнына қатаң қате шығарады, сондай-ақ әдепкі жолдан жергілікті орындау орталары әдейі алынып тасталған, сондықтан әлсіз резервтік нұсқаға түсу мүмкін емес.
- **Механикалық бақылау** — `CM-NO-LOCAL-RUNTIME` құрастыру алдындағы қақпа және онымен байланысты мутациялық сынақ құрастыру кезінде жергілікті орындау клиенті әдепкі жолда ешқашан құрылмайтынын растайды: кепілдік бұзылса, құрастыру сәтсіз болады.
- **Анықталған, бағалау бойынша реттелген резервтік тізбек** — *тексерілген* модельдер арасындағы провайдерден провайдерге ауысуға рұқсат етіледі және толық ашық, бұл үнсіз резервтік ауысуға тыйым салынғаннан принципті түрде ерекшеленеді: жұмыс қай қабілетті модельге жүктелгенін әрқашан білесіз.
- **WebSocket мониторингі нақты уақытта** — типтелген аударма оқиғалары тікелей тақтаға ағып келеді, ал SSH таратылған жұмысшылары арқылы кітап көлеміндегі тапсырма көрінетін және параллель түрде орындалады, қара жәшік емес.
- **Алдауға қарсы сынақ режимі** — мутациялық сынақтар, теріс растаулар, нақты жүйелік орындаулар және көру арқылы сапалық бақылау бірге "сынақтар сәтті өтті" деген жағдайда "мәлімет шынымен жұмыс істемейді" дегенді үнсіз жасыра алмайтындай етеді.

## Ең үлкен техникалық қиындықтар және оларды қалай шештік

- **Адал аударма құбырының кепілдігін беру (үнсіз құлдыраусыз).** Барлық модельдердің билігін LLMsVerifier көпірінде орталықтандыру арқылы шешілді, сондықтан бақылау үшін бір ғана шешім нүктесі бар, төрт анық маршруттау тармағы әрқайсысы болжаудың орнына қатты қате шығарады, жергілікті орындау резервтік нұсқалары әдепкі жолдан толығымен алынып тасталды, ал ережені құрастыру қақпасы және мутациялық сынақ арқылы бекітілді, егер кепілдік бұзылса, құрастыру сәтсіз болады.
- **"Сынақтар жасыл, мүмкіндіктер бұзылған."** Конституция осы істен шығу режимін тікелей атап, оны Алдауға қарсы сынақ режимі арқылы жеңеді: нақты пайдаланушыға көрінетін растаулар, іске қосылған нақты жүйелер (макеттер тек бірлік сынақтарында қолданылады), міндетті мутациялық сынақтар (мәліметті әдейі бұзып, сынақ қызыл түсуі *керек*), және шығысты шынымен көріп тексерілетін сапалық бақылау.
- **Ұзақ және әртүрлі форматтағы сапа.** Кітап көлеміндегі мәліметтер біркелкілік пен бюджетке қысым жасайды; көп реттік өңдеу арқылы шешілді, онда мәтін қайта қаралады, алдын ала талдау кезеңінде жұмыс көлемі бағаланады, ал аударма кеші аударманың бір бөлігі үшін екі рет төлеуден сақтайды.

## Технологиялық стек

- **Go** — таңдалды, себебі оның параллелділік примитивтері таралымды, аударманы және көптеген тарауларды бір мезгілде ағылшыннан ағытуды табиғи түрде қолдайды; жоғары параллелділік артқы жағы, `digital.vasic.translator` модулі.
- **Gin** — жылдам, минималды HTTP маршрутизаторы ретінде таңдалды, REST API бетіне қызмет көрсету үшін.
- **QUIC / HTTP/3 (quic-go)** — REST API бетіне төмен кешігумен, қазіргі заманғы тасымалдауды қамтамасыз ету үшін таңдалды, ол нашар желілерде де төзімді болып қалады.
- **gRPC + Protocol Buffers** — REST жүйесімен қатар жұмыс істейтін, күшті типтелген, жоғары өнімділіктегі қызметтік интерфейс үшін таңдалды, бұл бағдарламалық шақырушыларға арналған.
- **Gorilla WebSocket** — мониторингтік тақтаға тікелей ағылшын-аударма оқиғаларының ағынын тасымалдау үшін таңдалды.
- **PostgreSQL, SQLite, Redis** — әдейі үш деңгейге бөлінген: PostgreSQL — төзімді реляциялық деректер үшін, SQLite — жергілікті күйді сақтау үшін (сонымен қатар көпірдің расталған модельдер қоры `data/verified_models.db` базасын қолдайды), ал Redis — жылдам кэш ретінде.
- **unidoc/unioffice + unipdf** — қиын форматтармен жұмыс істеу үшін таңдалды: DOCX және PDF таралымдарын және қайта жаңғыртуды қамтиды, бұл көп форматты электрондық кітаптардың дөңгелек айналымды сақтауына мүмкіндік береді.
- **Cobra** — `unified-translator` және оның серіктес құралдарын басқаратын CLI фреймворкі ретінде таңдалды.
- **golang-jwt (JWT HS256)** — күйсіз API аутентификациясы үшін таңдалды, әрбір IP үшін токендердің шекті санымен және TLS/QUIC көлік қауіпсіздігімен бірге қолданылады, бұл бетті қатаң қорғауға көмектеседі.
- **LLMsVerifier көпір (`pkg/bridge`)** — негізгі бөлік: ең мықты расталған модельді және оның анықталған резервтік тізбегін алады, сонымен қатар "резервтік нұсқаға үнсіз көшу жоқ" кепілдігін қатаң сақтау нүктесі болып табылады.
- **Testify** — Go сынақ жинағы үшін таңдалды, оған арналған `provider_routing_test.go` және адалдық ережелерін қатаң сақтайтын өзгерістер қақпалары кіреді.
- **Docker / Podman (rootless) + Compose** — контейнерленген, таратылған орналастыру үшін таңдалды (`docker-compose.distributed.yml`), қауіпсіздік деңгейін жоғарылату үшін rootless Podman қолданылады.
