// 요약

LLM을 신뢰할 수 있는 제품으로 전환하는 소프트웨어를 설계하고 구축합니다.

주로 Go로 작업하며, 필요에 따라 Kotlin / Kotlin Multiplatform, TypeScript/React, Python, Swift, Shell을 사용합니다. 제 결과물은 일회성 앱들의 무리가 아니라 함대처럼 조직됩니다: 수십 개의 작고 분리된, 독립적으로 테스트된 모듈 위에 놓인 대규모 제품 애플리케이션이며, 모두 공유 엔지니어링 헌법을 Git 서브모듈로 상속합니다.

즉, 수정 사항이 모든 것에 전파되고, 새로운 제품은 검증된 부품으로 조립되며, 광고된 모든 기능은 증거를 생성하는 테스트로 뒷받침됩니다. 나의 북극성은 하나의 규칙입니다 — 기능은 실제 사용자가 사용할 수 있고, 이를 증명할 증거가 포착될 때만 완료됩니다. 이 페이지는 개요에서 개별 프로젝트로 이동하며, 각 프로젝트는 전체 제품 페이지로 연결됩니다.

// 내가 일하는 방식 — 거버넌스와 QA 우선

제품을 뒷받침하는 원칙.

제품보다 먼저인 원칙: 나는 녹색 체크마크를 제공하지 않으며, 실제로 작동한다는 증거와 함께 AI 시스템을 제공합니다.

HelixConstitution shipped

140개 이상의 레포지토리 함대를 통해 Git 서브모듈로 배포되는 보편적이고 상속 가능한 엔지니어링 규칙서. 블러프 방지 증거 게이트, 거짓 양성 면역, 데이터/호스트 안전성 및 커버리지 규칙을 코드화합니다; 프로젝트는 이를 강화할 수 있지만 절대 약화시킬 수 없으며, 각 거버넌스 게이트는 게이트 자체가 작동함을 증명하는 변이 테스트와 짝을 이룹니다.

더 읽기
