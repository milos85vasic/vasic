HONEST LIMITATIONS
------------------
* de is NOT yet translated: _content_de/docs does not exist. The DE PDFs were
  built from the EN masters as a MECHANISM proof (build-pdfs.sh reports the EN
  fallback on stdout). When real _content_de/docs lands, the same command emits
  genuinely German PDFs with no code change.
* RTL (ar/fa) + CJK (zh/ja/ko): dir/lang stamping and the whole pipeline work,
  but the pinned Liberation/DejaVu safe body stack in default-pdf.css does not
  carry Arabic/CJK glyphs. WeasyPrint would rely on fontconfig fallback (macOS
  has .SF Arabic / Noto Nastaliq / CJK faces) which may or may not be complete.
  Additionally validate-pdf.js OCR uses the 'eng' tessdata only (the box has no
  ara/jpn packs), so the visual.ocr check would under-count for genuine
  non-Latin content. These are noted, not faked. Today ar/ja builds PASS only
  because they fall back to Latin EN content.

deploy-langs.sh cycle, no --dry-run).
