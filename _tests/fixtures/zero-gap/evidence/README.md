## What this is

A deterministic corpus of TWO-FILE evidence stores (data-model.md "EvidenceRecord —
TWO files"): each store is `chain.jsonl` (the 9-field, verifier-native chain),
`sidecar.jsonl` (the rich record bound by `artifact_path = sha256:<line>`) and
`anchor.json` (`{head_digest, entry_count, anchor_strength}`).

* `golden-good/` — three healthy records, anchored at 3. Every adapter invariant holds,
  the upstream chain walk PASSes, the anchor PASSes.
* `golden-bad/<attack>/` — one attack each, plus `expect.json`:
  * `summary` — the component verdicts `zero-gap-evidence-chain.sh --verify` must print
    (a substring of its `VERDICT` line);
  * `invariants` — the adapter invariant ids (`I1`..`I9`) that must be reported; an EMPTY
    list means the attack leaves every adapter invariant holding and is caught ONLY by the
    anchor (`both-tails-truncated`, `delete-and-rechain`).

These stores keep `anchor.json` BESIDE the store, untracked — right for throwaway
fixtures only. `zero-gap-evidence-chain.sh --verify` is strict by default (an anchor with no
committed history is rc 2), so the proof verifies the corpus with `--allow-untracked-anchor`;
the real store's anchor is the tracked `docs/zero-gap/anchor.json`. Every chain file here is
canonical bytes, so it also satisfies I10 (the chain byte rule).

Paths inside the records (`/srv/zg-fixture/...`) are synthetic: no machine-specific path is
recorded. The anchor strength is `unknown` because no strength probe is run for a fixture —
`unknown` is the honest value without one; a real anchor written with `--remote` records
`policy`.
